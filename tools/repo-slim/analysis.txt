Note: git stores each distinct blob once, so identical files at different
paths are counted under whichever path reaches them first. This is not
cosmetic -- it reflects real storage. Checked on this history:

  * SEVEN blobs in NGSpeciesID's history are reachable at more than one
    path, and `git rev-list --objects` reports only one path for each:
      test/Supplementary_File1_reads.fastq == test/Supplementary_File2_reads.fastq
      test/Supplementary_File2_minibar.txt == test/Supplementary_File3_minibar.txt
      test/Supplementary_File3_primer.txt  == test/Supplementary_File4_primer.txt
      modules/.DS_Store                    == scripts/.DS_Store
      NGSpeciesID                          == isONclust
      cemetary/cluster_parallel.py         == modules/cluster_parallel.py
      modules/compute_shared_minimizers_probabilities.py ==
        scripts/compute_shared_minimizer_probabilities.py
    So the deduplication trap DOES bite here: scripts/.DS_Store would not
    have appeared on a removal list built from the object listing, and the
    three renamed Supplementary_File pairs are why KEEP names both spellings
    of each. This list is built from a tree walk, which is the only way to
    know any of that.

  * test/ccs.fastq.gz was committed as four `split` parts, part-aa..part-ad,
    365 MB together. They are four blobs, not one file, and archive_data.sh
    reassembles them (verified with `gzip -t`) before they are destroyed.

  * KEEP protects the five test/ files that are live in HEAD, plus the three
    historical spellings they share blobs with. Removing either spelling of
    a renamed pair removes the blob, and the live file with it.
